# Indian Market Momentum Dashboard — Master Development Prompt

## 1. Project Role

You are the lead full-stack developer, quantitative developer, UI/UX designer, and QA engineer for this project.

Build one professional web application for analyzing, ranking, and backtesting momentum strategies in the **Indian stock market**.

The application should be powerful enough for an experienced market participant while remaining simple enough for a beginner to understand.

Do not over-engineer the project.

Prioritize:

* Financial calculation accuracy
* Reliable market data
* Fast performance
* Clean modular code
* Easy future customization
* Professional UI/UX
* Mobile compatibility
* Simple maintainable architecture

# 2. Core Purpose

The application will:

1. Obtain historical and current Indian stock-market data.
2. Analyze stocks using Relative Strength (RS) momentum.
3. Rank stocks against their respective benchmarks.
4. Backtest monthly momentum portfolios.
5. Display current momentum rankings.
6. Compare strategy performance against benchmarks.
7. Generate charts, tables, analytics, and CSV reports.
8. Allow additional strategies to be added later.

The application should function primarily as an **expert momentum-analysis and backtesting dashboard**.

# 7. Monthly Momentum Strategy

Run the following strategy independently for each universe.

The core concept is:

**Stock Performance vs Benchmark Performance**

using Relative Strength.

---

# 8. Monthly Return Calculation

At every month-end, identify the **last valid trading day** of that month.

For each stock calculate:

`Stock Return % = ((Current Month-End Price / Previous Month-End Price) - 1) × 100`

Calculate the corresponding benchmark return:

`Benchmark Return % = ((Current Month-End Benchmark Price / Previous Month-End Benchmark Price) - 1) × 100`

Do not assume the calendar month's final date is a trading day.

Use actual available trading data.

---

# 9. Relative Strength

Calculate Relative Strength as:

`RS = Stock Return % - Benchmark Return %`

Example:

Stock return:

+8%

Benchmark return:

+3%

RS:

+5 percentage points

This means the stock outperformed its benchmark by 5 percentage points during the measurement period.

Use this exact definition consistently unless the user explicitly changes the strategy later.

---

# 10. Ranking

At each month-end:

1. Calculate monthly return for every eligible stock.
2. Calculate benchmark return.
3. Calculate RS.
4. Sort stocks by RS from highest to lowest.
5. Assign ranks.

Highest RS:

**Rank 1**

Rank each universe independently.

---

# 11. Top 5 Selection

Select the five stocks with the highest RS within each universe.

Therefore every month there will be separate selections for:

* NIFTY 50 Top 5
* Mid Cap Top 5
* Small Cap Top 5

---

# 12. Portfolio Capital

Default strategy capital:

**₹50,000 per universe**

Each universe represents a separate hypothetical portfolio.

For five selected stocks:

`Target Allocation = ₹50,000 / 5 = ₹10,000 per stock`

Use equal-weight allocation.

---

# 13. Share Quantity

Because stocks trade in whole shares for normal cash-market delivery positions, calculate:

`Shares = floor(Target Allocation / Entry Price)`

Show:

* Stock
* Entry Price
* Target Allocation
* Shares Purchased
* Actual Amount Invested
* Remaining Cash

Do not assume fractional shares.

---

# 14. Monthly Rebalancing

At each month-end:

1. Calculate new rankings.
2. Identify the new Top 5.
3. Close positions from the previous portfolio according to the defined execution convention.
4. Enter the newly selected Top 5.
5. Allocate capital equally.
6. Carry forward any uninvested cash.
7. Continue the process every month.

Run this independently for all three universes.

---

# 15. Backtest Execution Safeguard

Avoid look-ahead bias.

If rankings use the closing price of the final trading day of a month, the strategy cannot assume that the same closing price was known before that close.

Therefore define and display the execution convention clearly.

Preferred default:

**Signal Date:** Last trading day's close of the month
**Execution Date:** Next trading day's available price

If another convention is used, document it explicitly.

Never produce a backtest that accidentally uses future information.

# 20. Current Momentum Dashboard

In addition to historical backtesting, calculate current-month momentum.

For each stock:

`Current Month Return % = ((Current Price / Previous Month-End Price) - 1) × 100`

For the benchmark:

`Current Benchmark Return % = ((Current Benchmark Price / Previous Month-End Benchmark Price) - 1) × 100`

Then:

`Current RS = Current Stock Return % - Current Benchmark Return %`

Rank stocks dynamically according to Current RS.

This provides an **in-progress momentum ranking for the current month**.

Do not confuse the live ranking with the completed month-end ranking used by the backtest.

# 40. Important Backtesting Rules

Never introduce:

* Look-ahead bias
* Survivorship bias knowingly
* Future-price leakage
* Incorrect month-end assumptions
* Benchmark mismatches
* Silent missing-data substitution

If historical constituent membership is unavailable and today's constituent list is used for historical backtesting, clearly label this as a **survivorship-bias limitation**.

Do not present such a backtest as historically perfect.
